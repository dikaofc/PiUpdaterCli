# TypeScript

## Config (start from strict)
- `strict: true` (implied: noImplicitAny, strictNullChecks, strictFunctionTypes...), `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` when ready, `target: es2022+`.
- `isolatedModules`, `verbatimModuleSyntax` (type-only imports), `moduleResolution: bundler` for Vite-style projects.

## Type design
- Model domain with types first; `type` vs `interface`: interfaces for object contracts + merging in public APIs, `type` elsewhere.
- Discriminated unions over optional-flags: `type Res = {status:'ok';data:T} | {status:'error';error:Error}` — exhaustive `switch` narrows for free.
- Generics with constraints; never `any` (use `unknown` + narrow). `satisfies` to keep literal types while checking structure.
- `Readonly<T>` on params you mustn't mutate; branded types (`type UserId = string & {__brand: 'UserId'}`) for mixed ids.
- Utility types: `Pick`, `Omit`, `Partial`, `ReturnType` — prefer mapping to hand-written duplicates.
- Encapsulate `as` casts behind a validating function; `as` only at trust boundaries (API parse, storage read).

## What reviewers flag
- `any` leaks (grep); untyped `fetch` responses; `string` for ids/enums (literal unions instead).
- Unused generics; typing `Function`/`Object`; errors typed as `unknown` not caught.
- Autogenerated types drift (REST/DB) — regenerate, don't hand-patch.

## Refactor support
- `tsc --noEmit` + `jscodeshift` for mechanical edits; derive types from one source (zod/schema → `z.infer<...>`).

## Checklist
- [ ] strict on, no `any` (except pinned lib-boundaries with comment)
- [ ] Discriminated unions for multi-state values
- [ ] Unknown not any at I/O boundaries
- [ ] No duplication of shape definitions
- [ ] Build + typecheck pass clean
